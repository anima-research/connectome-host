- **`mcpl_restart` and `mcpl_deploy` no longer report a server as working when it isn't, and the MCPL admin receipts say what an agent-overlay replacement lacks.**
  - Both now fail when the server isn't connected afterwards. Before, a restart reported success while its own text read "NOT connected", and a deploy said "connected" without checking. A WebSocket server whose first dial fails comes back as a stub that keeps retrying, without the call throwing, so either could happen.
  - An agent-overlay entry under the id of a recipe or `mcpl-servers.json` server replaces that definition whole: its env is literal, and it never inherits the host environment. Since stdio children get only allowlisted host variables, the replacement runs without whatever the operator's definition provided that the entry lacks, and it can look healthy until its first call. `mcpl_deploy`, `mcpl_restart` and `mcpl_list` now say when a server runs such a replacement, and name what it lacks: env names (never values), a token, an `access` grant, or `inheritEnv`. The host logs the same at startup, and `mcpl_unload` of a replacement says that the operator's definition loads again at the next start.
