- `/update back` and `connectome update back` say what each way brings back in plain words: keeping the newer data brings the host back as it is now, answering new turns or holding them if it's quiesced; restoring the copy brings it back answering new turns, whether or not it's quiesced now, unless it had been quiesced from the Web UI before the Restart that took the copy: then it comes back holding them until "⏸ quiesced" in the Web UI's top bar is clicked. Their last line says that either way new turns are held first and turns in progress get up to 2 min to end, as Restart does, where both said the host "quiesces".
- `/update restart` and `/update back`, and `connectome update restart` and `back`, open with "Asking the host to restart" or "to go back", and that if it goes ahead new turns are held and turns in progress get up to 2 min to end, where they said "unless refused". When the host then stops for a service set up for updates, it says the service starts it again by itself, and that start makes the switch.
