- `scripts/connectome-doctor` reads a unit's output from its journal when the unit file names no log file, as `connectome service install`'s units don't, and `logs/agent.log` is missing or was last written before the unit started: the lines since the unit's latest start that hold a delivery or a failure, which journalctl's `-g` picks out, with journal times to the fraction of a second. Before, it read the host's recent failures, last delivery and gate dump from a `logs/agent.log` that wasn't there or was left from before.
- `scripts/connectome-doctor` sends its gate dump's `SIGUSR2` only to a host whose `/proc/PID/status` shows it catches the signal, so it no longer ends a host that is still starting, and waits up to 5 s for the host's `[diagnostics]` line.
- `scripts/connectome-doctor` reads the chronicle ingest stage from the active session's `records.log`, as `sessions.json` names it. Before, it read whichever session's the directory listed last.
- `scripts/connectome-doctor` says "can't be seen here", with the reason, of a stage it can't see, where it said never: the Discord stages when discord-mcpl's debug log isn't there, since discord-mcpl writes it only when `DISCORD_MCPL_DEBUG_LOG` names it, and a stage whose file or store it can't read.
- `scripts/connectome-doctor` counts every record in the last 400 KB of `logs/failures.log` as a failure, but the subscription GC's `subscription-gc-close`, which `connectome doctor` names apart, and makes a finding of a reply that wasn't delivered, or whose delivery wasn't confirmed, after the last one that was.
- `scripts/connectome-doctor`'s inference stage is the newest turn's call in the call log, a streamed call. Before, it was the newest call of any kind, so the host's start-up thinking-binding probe, or compression, read as the resident's inference. A subagent's turn and a streamed inference an MCPL server asks for are streamed calls too, so on a host with either, the stage's time and stop can be that call's and not the resident's. With no turn's call since the host last started, it says so, counting the other calls and keepalive pokes. A call whose `rawResponse`, or the response in it, isn't an object is read as one with no stop reason, where the ladder stopped at it.
- `scripts/connectome-doctor`'s inference-failure finding doesn't count when the call log's newest turn call came after the failure and succeeded: it says when that call was, and that the call log doesn't say whose call it was, so whether the agent that failed has recovered isn't known. When the call log can't be read, or there's none while inference failures are on record, or the part it reads has no turn's call and either starts after the failure or holds rows it can't read, its finding says whether a turn has succeeded since isn't known, and doesn't count either. `connectome doctor` shows a finding that doesn't count as a line, not a problem. The ladder run alone lists it with its other findings, and exits 1 when it has any.
- `scripts/connectome-doctor` takes `--data-dir` for a data directory other than `INSTALL_DIR/data`, and `--findings-json` for its findings as one JSON line, with no model call's error text, failure line or message preview: its inference stage names the call log file, each source of recent failures gives each kind's count and newest time and the command that shows the lines, and its Discord stage names the channel. The inference stage and each source's heading say that the text is left out, since it can quote a model provider or a person. `connectome doctor` runs it with both, and cuts each of its lines but the gate dump's at 300 characters.
