- `scripts/connectome-doctor` reads a unit's output from its journal when the unit file names no log file, as `connectome service install`'s units don't, and `logs/agent.log` is missing or was last written before the unit started. Before, it read the host's recent failures, last delivery and gate dump from a `logs/agent.log` that wasn't there or was left from before.
- `scripts/connectome-doctor` sends its gate dump's `SIGUSR2` only to a host whose `/proc/PID/status` shows it catches the signal, so it no longer ends a host that is still starting. `--no-signal` leaves the dump out.
- `scripts/connectome-doctor` reads the chronicle ingest stage from the active session's `records.log`, as `sessions.json` names it. Before, it read whichever session's the directory listed last.
- `scripts/connectome-doctor` says "can't be seen here", with the reason, of a stage it can't see, where it said never: the Discord stages when discord-mcpl's debug log isn't there, since discord-mcpl writes it only when `DISCORD_MCPL_DEBUG_LOG` names it, and a stage whose file or store it can't read.
- `scripts/connectome-doctor` counts every record in the last 400 KB of `logs/failures.log` as a failure, and makes a finding of a reply that wasn't delivered, or whose delivery wasn't confirmed, after the last one that was.
- `scripts/connectome-doctor` makes no inference-failure finding when the call log's newest turn call came after the failure and succeeded, and says when instead.
- `scripts/connectome-doctor` takes `--data-dir` for a data directory other than `INSTALL_DIR/data`, `--findings-json` for its findings as one JSON line, and `CONNECTOME_DOCTOR_WITHHOLD` for values to replace with their names where it reads them. `connectome doctor` runs it with all three.
