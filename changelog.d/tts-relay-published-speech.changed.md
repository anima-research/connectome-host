- The TTS relay (`modules.ttsRelay`) voices only what the agent's prose publishes: each message, once its publish is confirmed, as one text block on the channel it was published to. It used to stream everything the model wrote as it wrote it, tagged with the turn's channel, so voice clients spoke text the agent then kept back (a `skip_reply`, a silencing send, a private `think`), and received its thinking and tool calls. A spoken reply now starts when its message is posted, not while it is being written. A message sent with a tool call, such as discord-mcpl's `send_message` or a subconscious's `speak_in_channel`, isn't voiced, and neither is one published while the relay is reconnecting, which the host logs.
- The client's "thinking" follows the turn more closely. A turn that a tool ends, such as with `skip_reply`, now ends it too, where it used to stay on until the next turn. A failure the framework retries, or holds for a provider's wait, no longer ends it, so it no longer cancels the audio of the turn's earlier messages. When the framework moves a turn to a channel that addressed the agent mid-turn, the "thinking" moves with it. Several agents' turns on one channel, such as a sync subagent's on its parent's, share that channel's "thinking", which ends when the last of them ends. When the framework disposes a subagent's run with no end, the run is let go at the next start or end of one of the bot's turns, which comes with the subagent's parent, or when the relay is back, and the channel's "thinking" ends then if no other turn is left there. When the relay is back after a drop, every end it missed goes first, then a start for each channel a turn is on, and a turn that began and ended while it was away sends nothing. Stopping the host ends each open activation, and logs each it can't end because the relay is away, naming the channel left open. So the "thinking" no longer stays on after a drop, nor after the host stops while the relay is there.
- An interruption trims the message that was being voiced to the words heard, read across the messages sent for voicing on that channel since its activation there last started, or since the last interruption, passing over the "<name> says:" the voice client may speak before a message. It edits nothing when the words don't line up with them, or can't: after a turn was stopped (aborted, or ended by an error) on any channel, since the voice client's cancel is the bot's; after the bot started or spoke on another channel, which the voice client may voice too, or, for a channel's first message since its start or the last interruption, spoke on another channel since then; after the connection to the relay dropped; or past 64 messages. It leaves a message as it is when the agent edited or deleted it since posting it, or when discord-mcpl may have posted it as several Discord messages, since the id it reports is the last one's. It used to edit the newest message that matched the words' start, or the newest routed message when none did, so it could overwrite a message that was never voiced, or the one before, with words from another. The note to the agent now says which of its later messages weren't voiced before the interruption, or why nothing was trimmed.
- Blocks and activations carry the bot's identity whichever agent wrote the message. A subagent's messages now carry the bot's `username` (by default the agent's name), not the subagent's name, and `userId` defaults to `botId`, as the recipe documents, where it used to default to the name of the agent that wrote the message.
