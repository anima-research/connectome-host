- `bunx @animalabs/connectome-host setup discord`, typed on a terminal, sets a resident up on Discord. It works in the directory it starts in where that's empty or already the resident's, and in `~/resident` otherwise, says which before it asks anything, and, where it asks its first step, makes `~/resident` only once the answer is yes. On Linux with sudo and systemd, run as another user than `connectome`, setup first says what a shell would reach as the user running it, advises a user of the resident's own if it may get a shell, shows the one line that makes it, named `connectome`, for the person to run (setup never runs sudo), and asks whether to continue as this user, which Enter answers yes. On a Mac, without sudo or systemd, or run as `connectome`, it skips that step. It checks Bun 1.4.4 or later and Node, and installs the host with `@animalabs/discord-mcpl`. Before that, it adds Bun's default trusted packages and `term-sessions-mcp` to `trustedDependencies` in the directory's `package.json`, which Bun reads in place of its default list, a list it otherwise applies only to npm's own registry, and says what it added. Where it can't get that list from Bun or write it, it says why and goes on, and Bun may then run no install script of `term-sessions-mcp`'s, and through a mirror or a company registry none of the others'. It then makes `./connectome-host` an install that can take newer releases, with its own `connectome` command, serving `./data`, and starts the installed host once on a mock recipe. It checks an Anthropic API key with one real streamed call, at the `ANTHROPIC_BASE_URL` in `.env` when that sets one, naming the cause when it fails, and keeps the key in `.env`. It says which model the setup agent runs on and its prices, and starts that agent, which talks with the person in the terminal to set up the resident, and decides with them whether it gets a shell. Setup gives the agent the lines it can show the person again: the one that makes a user of the resident's own, and the one that turns linger on. Run again, setup goes on where it stopped, without asking again what it kept. Where linger is off for the resident's user, setup says so before installing anything, with the line that turns it on and who can run it, and goes on without asking. When the agent ends, setup prints the install's command that goes on with setup, or, once setup has finished, the one that changes what it set up.
- `connectome shell install`, an install's own command, installs the resident's shell, `term-sessions-mcp` 1.x, in the directory that holds the install unless a 1.x is there, and checks that node-pty opens a pty there, installing node-pty once more if it doesn't, and on macOS making its prebuilt `spawn-helper` executable. It changes no node-pty that loads from outside that directory, as through a link or from a directory above it: where that one doesn't open a pty, the command says where it loads from, and stops. Bun's add starts without the variables that a dotenv file of the directory the command starts in names, and the command refuses a Bun below 1.4.4 and an `--env-file` in `BUN_OPTIONS` or Bun's arguments. It stops on a Node above 24, writes no recipe and sets up no service. Setup's agent runs it when the person wants the resident to have a shell.
- A recipe's `modules.setup` gives its agent five tools, in readline mode on a terminal only: `setup--run` runs one command in the install's directory, without the stored secrets in its environment, by their names or as another variable's whole value, as stored or trimmed, and shows each stored secret's name where its value appears in the output; `setup--ask_secret` asks the person for a secret with nothing echoed and writes it to `.env` (0600), checking a `DISCORD_TOKEN`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY` or `ANTHROPIC_API_KEY` with its service first and storing none that's refused; `setup--check_model` asks the provider whether it offers a model to a stored key; `setup--discord` reads Discord with the stored bot token: the application's id, each server the bot is in with its owner, and each server's text and announcement channels under their categories, each with whether the bot can view it and send there, since from November 16, 2026 Discord lists the bot only the channels it can view; given a server, that server alone; or, given a server and the start of a username or server nickname, up to ten of its members, saying when more match. An answer longer than the inline text the framework gives the call, 24,000 characters unless a recipe or an agent sets fewer, gives the servers without their channels, then what fits, and says how many it left out and how to read the rest, or, for one server's channels, how the person copies the id of one left out; and `setup--finished` records that setup is finished and ends the conversation once that turn, and the turns that answer what the person typed meanwhile, have run. `setup--run` gives each command a file of its own, named in `CONNECTOME_SETUP_SHOWN`, where some of the install's own commands write their lines too, such as `connectome shell install`, and the install's `connectome` where it refuses to run; once the command ends, the person sees what was written there under "It said:", each stored secret shown by its name and each control character as a code, followed by a line saying it didn't finish where it was stopped at its time limit or ended by a signal. `recipes/setup.json` is setup's agent.
- Setup and its tools read and write `.env` in one form, the one Bun reads: empty lines, `#` comments, and `NAME=value`, `NAME="value"` or `NAME='value'`, each on one line, where a quoted value holds no quote of its own kind, `$` or backslash, an unquoted one no quote, backtick, `$`, backslash, space or `#`, and no line holds a tab or another ASCII control character. A `.env` with any other line is refused, naming the line by its number.
