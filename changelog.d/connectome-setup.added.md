- `bunx @animalabs/connectome-host setup discord`, typed on a terminal in a new directory, sets a resident up on Discord. Setup asks whether the resident gets a shell and whom it runs as (on Linux with sudo, a user of its own, made by one line setup shows for the person to run; setup never runs sudo), checks Bun 1.4.4 or later and Node, and installs the host with `@animalabs/discord-mcpl`, and `term-sessions-mcp` when the resident gets a shell. It then makes `./connectome-host` an install that can take newer releases, with its own `connectome` command, serving `./data`, and starts the installed host once on a mock recipe. It checks an Anthropic API key with one real streamed call, at the `ANTHROPIC_BASE_URL` in `.env` when that sets one, naming the cause when it fails, and keeps the key in `.env`. It says which model the setup agent runs on and its prices, and starts that agent, which talks with the person in the terminal to set up the resident. Run again, setup goes on where it stopped, without asking again what it kept. Where linger is off for the resident's user, setup says so before installing anything, with the line that turns it on. When the agent ends, setup prints the install's command that goes on with setup, or, once setup has finished, the one that changes what it set up.
- A recipe's `modules.setup` gives its agent four tools, in readline mode on a terminal only: `setup--run` runs one command in the install's directory, without the stored secrets in its environment, and shows each stored secret's name where its value appears in the output; `setup--ask_secret` asks the person for a secret with nothing echoed and writes it to `.env` (0600), checking a `DISCORD_TOKEN`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY` or `ANTHROPIC_API_KEY` with its service first and storing none that's refused; `setup--check_model` asks the provider whether it offers a model to a stored key; and `setup--finished` records that setup is finished and ends the conversation after that turn. `recipes/setup.json` is setup's agent.
- Setup and its tools read and write `.env` in one form, the one Bun reads: empty lines, `#` comments, and `NAME=value`, `NAME="value"` or `NAME='value'`, each on one line, where a quoted value holds no quote of its own kind, `$` or backslash, an unquoted one no quote, backtick, `$`, backslash, space or `#`, and no line holds a tab or another ASCII control character. A `.env` with any other line is refused, naming the line by its number.
