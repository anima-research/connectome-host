- `bunx @animalabs/connectome-host setup discord`, typed on a terminal, sets a resident up on Discord. It works in the directory it starts in where that's empty or already setup's, and in `~/resident` otherwise, and says which first. Where `~/resident` holds other files and isn't setup's either, it stops, saying so. On Linux with sudo and systemd, before it installs anything, it advises a user of the resident's own and asks whether to go on as the user who ran it. It installs the host and `@animalabs/discord-mcpl`, makes the install, starts its host once with a test setup that calls no model, checks the Anthropic key with one call, keeps the key in `.env` readable by the person alone, and starts the host's own setup agent, which talks with the person in the terminal. Run again, the agent picks up where it stopped.
- `connectome shell install`, an install's own command, installs the resident's shell, `term-sessions-mcp` 1.x, in the directory that holds the install unless a 1.x is there. It lists Bun's default trusted packages and the shell's own in that directory's `package.json` `trustedDependencies`, and checks that node-pty opens a pty there, installing node-pty once more if it doesn't and it loads from inside that directory.
- A recipe's `modules.setup` gives its agent four tools, in any mode, made for readline mode on a terminal: `setup--run` runs one command in the install's directory, without the stored secrets and the providers' keys in its environment, and gives back each of their values that it prints, as stored, by its name, but for a value shorter than 8 characters and a value that the cut of a long output runs through; `setup--ask_secret` asks the person for a secret with nothing shown as they type, checks a Discord token or a provider key once, and stores it in `.env`; `setup--discord` reads Discord with the stored bot token, so that the person copies no id by hand: the application's id, and each server the bot is in with its owner and its text and announcement channels, each with whether the bot can send there, or one server, or a server's members whose username or nickname starts with what it's given; `setup--finished`, in readline mode, ends the conversation when its turn ends. In that conversation a turn's wait has no time limit, a refused turn says how to start a new conversation, `/help` lists the three commands setup uses, and the host's own diagnostics go to `readline-error.log` from before its extensions load.
