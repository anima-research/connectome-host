- `bunx @animalabs/connectome-host setup discord`, typed on a terminal, sets a resident up on Discord. It works in the directory it starts in where that's empty or already setup's, and in `~/resident` otherwise, and says which first. On Linux with sudo and systemd, before it installs anything, it advises a user of the resident's own and asks whether to go on as the user who ran it. It installs the host and `@animalabs/discord-mcpl`, makes the install, starts its host once with a test setup that calls no model, checks the Anthropic key with one call, keeps the key in `.env` readable by the person alone, and starts the host's own setup agent, which talks with the person in the terminal. Run again, the agent picks up where it stopped.
- `connectome shell install`, an install's own command, installs the resident's shell, `term-sessions-mcp` 1.x, in the directory that holds the install unless a 1.x is there. It lists Bun's default trusted packages and the shell's own in that directory's `package.json` `trustedDependencies`, and checks that node-pty opens a pty there, installing node-pty once more if it doesn't.
- A recipe's `modules.setup` gives its agent three tools, for readline mode on a terminal: `setup--run` runs one command in the install's directory, without the stored secrets and the providers' keys in its environment, and gives back each of their values that it prints, as stored, by its name; `setup--ask_secret` asks the person for a secret with nothing shown as they type, checks a Discord token or a provider key once, and stores it in `.env`; `setup--finished` ends the conversation when its turn ends. In that conversation a turn's wait has no time limit, a refused turn says how to start a new conversation, `/help` lists the three commands setup uses, and the host's own diagnostics go to `readline-error.log` from before its extensions load.
