- A subagent's failure that isn't the host's own reaches its parent as fixed words for its class, where the parent read the error's message: "the model call failed (rate_limit)", "the model call failed (timeout, network or server)", "the provider asked to wait 1200 s, which a subagent's run doesn't sleep", or "the turn failed" ("it couldn't be set up" for a run that didn't start). That holds for the synchronous tool result and the asynchronous "[Subagent '<name>' failed]" notice alike. An agent-framework error's message can carry a provider's words, and the host can't tell them from any other, so a parent no longer reads an error's own wording, the framework's included. The host's own failures, such as a time limit or no concurrency slot, keep their words and remedies. The message goes to the operator's log first, as `[subagent] <name> stopped: <message>`, or `[subagent] <name> didn't start: <message>` for a run that didn't start, and stays the subagent's status message.
