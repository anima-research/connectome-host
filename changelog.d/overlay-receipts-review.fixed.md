- `mcpl_restart` keeps its overlay note when the restart throws, and an `mcpl-servers.agent.json` that can't be read no longer turns a successful restart into "mcpl_restart failed": the receipt reports the restart and says the file couldn't be read, without quoting it. The overlay-replacement receipts no longer report `AGENT_TIMEZONE`, which the host sets over every server's mapping, as lacking, and they do report a replacement that names a different `access` grant as lacking the operator's. A malformed entry in `mcpl-servers.agent.json` no longer stops the host from starting. Two shapes did: a `null` entry, and `args` that isn't a list. Now an entry that isn't an object, or has a field of the wrong kind (a `disabled` that isn't true or false, non-text `command`, `url`, `token` or `access`, `args` that aren't a list of text, an `env` that isn't a map of text), is skipped by the boot, which logs it, and the operator's definition loads. `mcpl_list` names it as malformed, and no receipt counts it as replacing anything. Only `disabled: true` tombstones a server, everywhere. A replacement whose `access` names a host variable is named, as one whose `token` does. A hand-edited `access` grant name is read trimmed, as `mcpl_deploy` writes it, so the host asks for the grant the receipts compare. A hand-edited entry that names both a `command` and a `url` is read by the connection agent-framework opens for it, which an explicit `transport` decides.
