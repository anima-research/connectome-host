- A fork or spawn that waits for a subagent slot is now created with what was resolved at its call, which is what its receipt describes. Its tool rules are still applied when it's created, as before, so a requested tool registered during the wait is usable. Before, it read the caller's settings again when a slot freed: the system prompt (for a fork that names none), the prose routing, and the output limit when the call gives none and no subagent default is configured. A fork or spawn whose caller was gone by then got the framework's default prose routing and, when neither the call nor a subagent default sets one, a 4,096-token output limit; a fork that names no prompt also got the research-assistant prompt. Each now keeps its caller's values from the call.
- A fork or spawn is now refused when its stream wouldn't read its whole orientation and its whole task in its first context. Each message in a stream's context is capped alone at 10,000 tokens: the cap counts a message's text and string tool results, keeps the message's beginning, and cuts or drops what doesn't fit, while tool calls pass whole. Before, the launch ran, and the stream read only the part of a long task that fit.
  - **What's checked is what the stream reads,** in the compiled context, not a prediction of the cap:
    - for a spawn or a parentless fork, its orientation and its task, each its own message and whole;
    - for a structural or fallback fork, its result's head (everything through the return instruction), and the whole task in its own fork call. Both the parent's call and the fallback's synthetic one carry it, so a long task alone doesn't refuse a fork that has a call.
  - **The refusal names each part that was cut, and what to do:**
    - a long task: shorten or split it, or put the detail in a file and pass the path, giving a spawn a tool that can read it (a fork's own tools must be able to);
    - a spawn's orientation, which names its tools in full: give the spawn a shorter tools list;
    - a fork's orientation: launch it as `subagent--spawn` with a short tools list instead; for a fork that would inherit its parent's context, the refusal adds that a spawn inherits none of it.
  - **The refusal is never retried, and never read as a rate limit:** it's the launch's outcome, not a provider failure.
  - **Async launches:** an async launch still answers at once with its receipt. Its refusal comes afterwards as the subagent's failure notice, by the path every async failure takes: the notice is added to the primary agent's context, and an inference is requested for the agent that launched it.
