- Modern MCP (2026-07-28) servers can be configured on every surface: recipe `mcpServers`, `mcpl-servers.json`, the agent overlay and `mcpl_deploy`.
  - An `http(s)://` `url` is a modern server over Streamable HTTP. `"protocol": "modern"` runs a stdio `command` as one. `ws(s)://` stays MCPL over WebSocket.
  - A recipe may now override `protocol` and `requestTimeoutMs` on a file-defined server. A recipe `url` with an `http(s)://` scheme makes that server modern over HTTP and sets aside the file's stdio launch. A `ws(s)://` override works as before.
  - `mcpl-servers.json` entries now carry `url`, `transport`, `token`, `access`, `protocol` and `requestTimeoutMs` through to the framework. Before this the loader passed none of them on, not even `access`, which the file's type already declared.
  - Every entry is checked by agent-framework's own rules (`resolveServerBinding`, `serverConfigProblems`): a bad recipe or file entry stops startup, as does a recipe override that doesn't fit the file's server, a bad overlay entry is skipped with a logged reason (an operator server it would have replaced keeps running), and `mcpl_deploy` refuses one before saving it. A recipe entry with its own `command` or `url` that agent-framework can't use now fails recipe validation; agent-framework 0.21 couldn't connect any of these either.
  - Agent-deployed modern servers carry no MCPL capability mask, since they have no MCPL surface.
  - `mcpl_list` and the web panel show each server's family, negotiated revision and transport, and the target that transport actually uses. `mcpl_deploy` shows the same for a server it connected, and warns when the server's credential would cross the network unencrypted, which agent-framework otherwise reports only in the host's log.
  - `/mcp list` and the web panel's registry show each `mcpl-servers.json` entry's target as the framework would bind it, with its family and transport: an entry with both `command` and `url` and no `transport` runs its command. An entry the framework refuses is still listed, with the reasons it would stop startup.
  - `/mcp add` on an entry with a `url` replaces that network target with the command it names, keeping env and the other settings.
  - Requires an agent-framework release with modern MCP support.
