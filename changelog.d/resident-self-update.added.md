- `modules.selfUpdate` gives an agent `lifecycle--update`, its own `/update`, off by default. Its actions:
  - `check`: what's out and what it costs, what the host runs, an install under way, an armed restart, and how the last switch ended. Once a release newer than the running one is installed, it also names `notes` and the file it reads.
  - `notes`: once a release newer than the running one is installed, the notes of every release after the running one, up to and including the installed one, from the installed release's own `CHANGELOG.md`. When it has none to give, it refuses and says why.
  - `install`: installs the newest release beside the running one, answering once the install has begun.
  - `restart` and `back`: armed for the host's first quiet moment, once nothing the host counts as in flight is still going here, such as a turn, subagent run, background script, session switch, operator's work or credential action, and each fleet child says nothing is going there, such as a turn or background script. The host then switches as Restart or Go back does, and exits 75 for its service to start it again. `back` takes `data: keep` or `data: restore`.
  - `cancel`: disarms before the restart begins.

  Its description tells the agent that the person who runs its install can't call it, and sees the same with the install's own command, `<install>/connectome update`, from a shell beside a headless host, or `/update` in the host's terminal. Where the person's own words ask them to act, as on a release that needs a newer Bun or a host that isn't an install, the agent is told what the person who runs its host does.

  `restart` and `back` arm only on a headless host started with `CONNECTOME_SUPERVISED=1` in its environment, which `connectome service install` sets only for a service that restarts the host when it exits with 75 and with 1. A service written by hand needs the line and both restarts. Anywhere else they refuse and say why, since a restart there could leave the host stopped until someone started it. A host still busy at the quiet moment, a fleet child included, keeps the restart armed for a later one, at least a minute on, and the host serves meanwhile. An operator's Restart or Go back takes an armed restart's place. An armed restart lasts only while its host runs. When the host stops for any other reason than the switch itself before it begins, such as `connectome service stop`, a signal, `/quit` or the socket's `shutdown`, it records that, and its next start's `check`, `/update` and bare `connectome` say it didn't go ahead, with the stop as the reason. A `SIGKILL` or a crash records nothing, and a record the host can't write is a line in its log instead. The agent can arm it again once the host is back. `/update` shows an armed restart, what its last try waited on, and one that didn't go ahead and why, and so does `/healthz` under the `ops` scope; without it, `/healthz` keeps their versions, times, names and counts, and empties the reasons.
