- `modules.selfUpdate` gives an agent `lifecycle--update`, its own `/update`, off by default: `check`, `notes` (the notes of the releases after the running one, up to the one installed), `install`, `restart` and `back` (armed for the host's first quiet moment, once nothing is in flight here or on any fleet child), and `cancel`.

  `restart` and `back` arm only on a headless host started with `CONNECTOME_SUPERVISED=1` in its environment, which `connectome service install` sets only for a service that restarts the host when it exits with 75 and with 1. A service written by hand needs the line and both restarts. Anywhere else they refuse and say why. A host still busy at its quiet moment keeps the restart armed and tries again at least a minute later, serving meanwhile. An operator's Restart or Go back takes an armed restart's place.

  An armed restart lasts only while its host runs. When the host stops first for any other reason, its next start's `check`, `/update` and bare `connectome` say it didn't go ahead, with the stop as the reason; a crash or a `SIGKILL` records nothing, and a record the host can't write is a line in its log instead. `/update` shows an armed restart, what its last try waited on, and one that didn't go ahead and why, and so does `/healthz` under the `ops` scope, which without that scope empties the reasons. A `cancel`, which any agent with the tool can make whoever armed it, leaves that record too, naming the agent that cancelled. A switch an agent armed names that agent in its mark and in each journal line written from it, and `check`'s line for the last switch says which agent asked for it.
