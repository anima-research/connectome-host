- A forked or spawned stream is told what it runs on before its first inference, and its caller's receipt describes the same launch. `subagent--fork` and `subagent--spawn` resolve one launch description at the call, then create the stream from it.
  - **What the description covers:** lineage and depth, model, provider, system-prompt source, strategy, head and recent windows, message cap, compression model, stream budget, output limit, prose routing (with what the mode does to the stream's plain text) and tool rules.
  - **The caller's values:** each setting is set beside the caller's value at the call. A setting the caller doesn't report is marked as not compared, never assumed equal. A fork's summary sorts every setting into differs, same, and not compared.
  - **Where it appears:** a fork's intention-framed tool result (on the structural and the fallback path) states the description verbatim, after the framing and before the return instruction and the restated intention. A spawn and a parentless fork get it as their own first message (a parentless fork's ends with the return instruction), followed by their task alone in a message of its own. Each message in a stream's context is capped alone at 10,000 tokens, and the cap keeps a message's beginning. So a spawn's orientation and task each have the whole cap, and a structural fork's result leads its message, ahead of the other results its parent's turn returned. The native formatter merges the orientation and task messages into one user turn; the anthropic-xml and openai-responses formatters send them as two consecutive user turns.
  - **Two lists are partial:** the caller's restriction, and the tools a fork has beyond its parent's, are named up to ten and the rest counted. The stream's request defines every tool it can call. Everything else is named in full: a spawn's or parentless fork's whole surface, the names a spawn's caller listed, and the parent's tools a fork lacks.
  - **What the stream adds at its start:** what actually happened when it was created. That covers which inheritance path ran (cut at the fork call, or the parent's whole compiled context at that moment because the call wasn't in it), its context budget as created, its prose routing when there is no calling stream to inherit it from, and the tools it is shown at its first inference. A fork's tools are compared with what its parent is shown: every tool it lacks is named, and the tools it has beyond its parent's are named up to ten. A spawn's, and a parentless fork's, are listed in full. It also sets the agent settings the stream is created with, which are the framework's defaults, against its parent's or caller's: extended thinking, provider parameters, prompt caching and its TTL, the prefill user message, the same-round think-text policy, refusal handling, and the tool-result and tool-wrapper prose guards. It names each one that differs.
  - **Receipts:** the async receipt says whether the launch is starting or queued for a slot. A sync result carries the description as `launch`, and a detached return appends it.
  - **The size check:** the prompt-size check before a fork's or spawn's first inference now counts the orientation, since the first request carries it. So a launch whose context sits within the orientation's length of `maxPromptTokens` is refused with "Prompt too large" before it starts, where it used to start.
  - Fork defaults don't change.
