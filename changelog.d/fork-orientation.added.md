- A forked or spawned stream is told what it runs on before its first inference, and its caller's receipt describes the same launch. `subagent--fork` and `subagent--spawn` resolve one launch description at the call, then create the stream from it.
  - **What the description covers:** lineage and depth, model, provider, system-prompt source, strategy, head and recent windows, message cap, compression model, stream budget, output limit, prose routing (with what the mode does to the stream's plain text) and tool rules.
  - **The caller's values:** each setting is set beside the caller's value at the call. A setting the caller doesn't report is marked as not compared, never assumed equal. A fork's summary sorts every setting into differs, same, and not compared.
  - **Where it appears:** a fork's intention-framed tool result (on the structural and the fallback path) and a spawn's task message state the description verbatim.
  - **What the stream adds at its start:** what actually happened when it was created. That covers which inheritance path ran (cut at the fork call, or the parent's whole compiled context at that moment because the call was no longer in it), its context budget as created, its prose routing when there is no calling stream to inherit it from, and the tools it is shown at its first inference. A fork's tools are compared in full with what its parent is shown; a spawn's are listed in full.
  - **Receipts:** the async receipt says whether the launch is starting or queued for a slot. A sync result carries the description as `launch`, and a detached return appends it.
  - Fork defaults don't change.
