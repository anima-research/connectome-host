- Once the release offered is installed, `/update` and bare `connectome` say to take it with the restart alone, where they said to install it and then restart, beside the line saying it was installed. So does the `[update]` line the host logs when it first sees that release offered, if it's installed by then. `lifecycle--update check` gives the same line. For a headless host, that logged line names the install's own command by its full path, since its log is read in a shell, where `/update` isn't a command. `connectome update`'s own lines, and the update lines bare `connectome` prints, spell `connectome update` as the shell running them can run it: plain only where that shell finds the install's own command first on `PATH`, and by its full path otherwise.
