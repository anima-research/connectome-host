- `fleet--peek` returns a child's events without a failure's own text. An `error` or `attemptError` at any depth, such as a failed node's in a tree snapshot, reads `"left out"`, so a parent still sees that something failed. An event's `stack` and `providerErrorCode`, an `ops:alert`'s `message` and `data`, and an `errorType` of `safety` are left out. These fields can carry a provider's error text or a refusal's category, and a parent agent read them there. Streamed chunks (`inference:tokens`) are left out too, before `lines` is counted, since they carry a child's text before the provider may refuse it; the final reply of a child's main agent is in its `inference:speech`. A reply that the provider refuses at its end, with no retry, can still show there, as on earlier releases, since nothing in a child's events marks it. Everything else in each event stays, such as its type and time, `errorType`, `httpStatus`, `retryable`, `shownReason`, speech and tool calls, and the child's event buffer keeps each event whole. The result's `note` says what is left out; the tool's description is unchanged. A parent no longer reads the text in these fields, the host's own errors included, only that something failed. Fields with other names pass as they came, such as an MCPL server's `detail` or `stderrTail`, and a command's output.
